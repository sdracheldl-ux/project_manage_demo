## 一、数据输入设计

智能体取数清单（全部为平台已具备的数据能力）：

| # | 数据项 | 平台字段/入口 | 在月报段落中的作用 |
| --- | --- | --- | --- |
| 1 | **项目简介** | 项目简介字段（标准模板填报） | 概况交代（仅首次）：引进方式、选址、分期、产值/就业/纳税 |
| 2 | **计划投资总额** | 投资金额字段 | 概况交代：总投资体量 |
| 3 | **产业类别** | 产业类别字段 | 概况交代（可选） |
| 4 | 人工更新的进展 | 进展时间线 normal 条目 | 本月关键动态主体 |
| 5 | 阶段变化 | 系统事件（阶段流转） | 时间线节点句 |
| 6 | 关键决策节点 | 决策节点条目 | 时间线节点句 |
| 7 | 协同方反馈 | 分派任务 + 反馈入口（反馈人/时间/正文） | 协同推进句群 |
| 8 | 项目移交 | 移交记录（移交/接收单位、目标阶段） | 移交单句 |
| 9 | 当前阶段 | 项目当前阶段 | 开头定位 + 状态收尾 |

## 二、项目简介结构化解析

项目简介按标准模板填报，本质是**半结构化文本**，智能体可直接按模板槽位提取：

| 模板槽位 | 提取内容 | 月报用法 |
| --- | --- | --- |
| 引进时间 + 招商方式 | 「于____年__月通过__招商引进」 | 开头背景（可选） |
| 选址 + 总用地 | 「选址在__，用地__亩」 | 概况句 |
| 计划总投资 | 「总投资__亿元，分__期建设」 | 概况句 |
| 各期投资/用地/建设内容/完工时间 | 一、二、三期明细 | 进度对照（当月动态涉及某期时关联该期建设内容） |
| 达产后产值/就业/纳税/人才 | 体量四项 | 概况句尾（月报惯例：满产年产值约 120 亿） |

解析容错：未按模板填报（自由文本）时，降级为整段压缩成一句概况（≤50 字）或省略概况句。

## 三、输出设计：月报段落模式（唯一模式）

取消现有「结构化四段式」，只保留**记叙文段落**输出，直接可粘贴进月报「项目洽谈」板块。

### 3.1 概况句规则

月报写作惯例：概况在项目首现时一次性交代，续报不再重复。按此做成**自动判断**，与历史总结存档机制联动：

| 场景 | 判断依据 | 概况句 |
| --- | --- | --- |
| 首次纳入月报 | 该项目无任何历史月份总结存档 | ✅ 自动生成 |
| 续报项目 | 已有历史月份总结存档 | ❌ 省略，直接「本月，项目处于…」开头 |

手动开关兜底：弹窗提供「含项目概况」勾选项——首次自动勾选，续报默认不勾，用户可手动补概况。应对两种例外：

1. 领导要求重点汇报某个续报项目、段落被单独摘出时，补上概况才有上下文；
2. 项目体量信息有更新（如投资额调整、增加分期），需要重新交代。

### 3.2 段落骨架

```
【项目名】：{仅首次/勾选时：概况句}
本月，项目处于{阶段}。{X月X日，动态1；X月X日，动态2…（阶段流转/决策节点/移交融入时间线）}。
{协同推进方面：A单位反馈…；B单位反馈…}。
{问题方面：…，已于X月X日通过…协调}。
目前，{当前状态}。下一步，{计划+时间目标}。
```

六要素按信息有无自动取舍，某维度本月无数据则整句跳过，不留空段。

### 3.3 生成示例（续报形态，无概况句）

> **智能网联汽车测试基地项目**：本月，项目处于签约阶段。4月8日，区主要领导带队赴企业总部会谈，双方就二期用地规模达成一致，拿地规模由80亩提升至95亩；4月15日，项目由在谈移交至签约阶段（区投促局→园区招商部）；4月18日，决策节点「投资协议审核」通过。协同推进方面，规划局反馈土地调规方案已完成公示，预计5月初出让；企服局反馈项目公司注册材料已受理。问题方面，企业提出的电力增容诉求，已于4月20日通过委领导专题会明确由供电公司纳入年度改造计划。目前，投资协议文本已报投促委会审议。下一步，争取5月完成土地挂牌，6月正式签约。

## 四、写作规则

| 规则 | 说明 |
| --- | --- |
| 概况一次性 | 仅首次纳入月报生成概况句，续报省略；可用「含项目概况」开关手动补 |
| 时间线合并 | 进展/系统事件/决策节点/移交按时间统一编排，冠「X月X日」；同日多事件合并一句 |
| 协同反馈句式 | 「{协同单位}反馈，{反馈要点}」；仅取本月时间窗内反馈 |
| 移交单句 | 「X月X日，项目由{原阶段}移交至{新阶段}（{移交单位}→{接收单位}）」 |
| 风险成对出现 | 问题 + 应对措施同句呈现（仿月报「资金缺口较大→专题会明确融资方案」），不用 ⚠ 列表 |
| 事件排序 | 时间正序（月报惯例），最新状态放「目前」句 |
| 下一步 | 优先取本月最新进展中的计划表述，无则按当前阶段惯例提示 |
| 篇幅 | 300~500 字；超限按「本月动态 > 协同反馈 > 概况」优先级裁剪 |
| 数据缺失 | 某维度本月无数据则整句跳过，不留空段 |

## 五、历史月份总结管理

### 5.1 存储

按「项目 + 年月」存档，每项目每月最多一份正式总结。存档字段：

```
{ projectId, ym, content, generatedAt, generatedBy, sourceSnapshot }
```

- `content`：用户最终确认保存的版本（AI 原稿经编辑后以编辑版为准）
- `sourceSnapshot`：生成时的数据快照摘要（记录条数/阶段），用于溯源

### 5.2 生成与存档规则

1. 打开弹窗默认生成**本月**摘要（不自动存档，仅预览）
2. 点「保存为本月总结」→ 存档写入；该月已有存档时二次确认覆盖
3. 未保存关闭弹窗不留档，避免半成品污染历史记录
4. 概况句判断读取本存档表（有历史存档 = 续报）

### 5.3 查看/复制历史

- 弹窗顶部月份选择器：本月（可重新生成）/ 历史月份（只读展示当月存档，可复制）
- 每条历史记录标注存档时间与存档人，支持溯源
- 汇总场景（写月报时）：可按月份连续复制多个项目的当月总结
- 历史月份「保存」变「覆盖存档」（需确认）

## 六、交互流程

```
详情页进展区【AI 月度摘要】按钮
  └─ 弹窗（月份选择器 + 「含项目概况」勾选）
      ├ 本月：进入即生成月报段落（可编辑）→ 保存为本月总结 / 复制
      └ 历史月份：只读展示存档段落 → 复制 / 覆盖存档（确认后）
```

弹窗底部按钮：`重新生成` / `保存为本月总结` / `复制文本` / `关闭`。

## 七、边界与口径

| 场景 | 处理 |
| --- | --- |
| 本月无任何记录（进展/节点/反馈/移交均无） | 不生成，提示「本月暂无项目动态」 |
| 仅概况无动态 | 不生成（概况是静态信息，单独成段无汇报价值） |
| 同月重复生成 | 预览可反复生成；存档需二次确认覆盖 |
| 续报但手动勾选概况 | 正常生成概况句（取最新基础信息） |
| 年初跨年月份 | 月份选择器自然涵盖，无需特殊处理 |
