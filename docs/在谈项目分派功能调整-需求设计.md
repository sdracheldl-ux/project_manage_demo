# 在谈项目分派功能调整 - 需求设计

> 版本：v1.0　|　日期：2026-09-09　|　状态：待确认
> 关联：《在谈项目移交功能-需求设计》v1.1（已实施）

## 1. 需求背景与目标

现分派机制：一次分派选择 N 个接收单位，但只能填写**一份**协同事项说明，所有单位共用；且对接收单位无反馈时限要求，发起方难以跟踪"多久该有一次反馈"。

调整目标：
1. **分组分派**：一次分派中可配置多个「单位组」，每个（或每几个）接收单位对应**各自的**协同事项说明；
2. **反馈频率要求**：每组设置「每 X 天至少提交一次反馈」，作为协同跟踪依据。

## 2. 现状机制（改造基线）

| 项 | 现状 |
|------|------|
| 分派弹窗 AssignModal | 接收单位（多选）+ 协同事项说明（1 份，选填）+ 附件 |
| 记录拆分 | 提交后按单位拆分为多条 `assignList` 记录，`content` 全部相同 |
| 记录结构 | `{ id, toDeptKey, toDeptName, assignTime, content, attachments, status, acceptTime, finishTime, feedbacks[] }` |
| 反馈 | FeedbackModal 支持多次反馈，反馈后给发起方发站内信 |
| 展示 | 分派 tab 按单位卡片展示：状态、协同事项、反馈时间线 |
| 消息 | 分派时每单位一条【协作任务分派】站内信 |

## 3. 功能设计

### 3.1 分派弹窗改造（AssignModal）

表单由「单组」改为 **Form.List 动态多组**：

```
┌ 组1 ────────────────────────────────┐
│ 接收单位*  [科创局          ] ×      │   多选，跨组不可重复
│ 协同事项说明* [请协助对接高企认定…]    │   组级说明
│ 反馈要求*   每 [3] 天至少提交1次反馈  │   数字 1~99，默认 3
└──────────────────────────── [删除] ┘
┌ 组2 ────────────────────────────────┐
│ 接收单位*  [未来科技城, 企服局  ]     │
│ 协同事项说明* [请评估载体与租金方案]   │
│ 反馈要求*   每 [7] 天至少提交1次反馈  │
└──────────────────────────── [删除] ┘
[＋ 添加单位组]
附件（整体共享一份，不变）
```

规则：
- 至少 1 组；组内接收单位必选（≥1）、事项说明必填（≤500 字）、频率必填（1~99 天整数）；
- **跨组单位互斥**：后组已选单位在前组下拉中禁用/校验提示；
- 附件保持整体一份（所有组共享，避免重复上传）。

### 3.2 数据结构扩展

分派记录（按单位拆分后）新增字段：

```js
{
  ...,
  content,               // 本组协同事项说明（组级 → 拆分后同组单位相同）
  feedbackEveryXDays: 3, // 新增：反馈频率要求（天）
  // attachments 仍为组共享
}
```

存量 mock 种子同步补 `feedbackEveryXDays`（科创局 3 / 企服局 7 / 未来科技城 7），并把种子时间改为**相对当前时间**生成，保证逾期状态演示效果可控。

### 3.3 分派 tab 展示增强

每条分派记录卡片：

- 协同事项说明旁新增频率标签：`⏱ 每3天至少反馈1次`；
- 新增**反馈达标状态**（仅 processing 状态计算，done 不展示）：
  - 从分派时间（或最近一次反馈时间）起算，超过 X 天未反馈 → 红色 Tag `已超X天未反馈`；
  - 未超期 → 灰色 Tag `最近反馈：MM-DD HH:mm` 或 `暂无反馈`；
- 接收方视角同样可见该要求（作为提交反馈的时限提示）。

### 3.4 消息提醒文案

分派站内信内容追加频率要求：

> 您有一条来自"市投促局"的"项目名"协作配合任务，请**每3天至少提交1次反馈**，请及时查看并跟进处理。

逾期自动催办（定时推送）不在本次范围（demo 为前端 mock，无定时任务），仅做页面内状态标识。

### 3.5 不变项

- 反馈提交（FeedbackModal）、标记完成、反馈时间线逻辑不变；
- 分派权限仍仅发起方；接收方可见范围、hasAccess、移交逻辑均不变；
- 列表页、其他阶段模块不动。

## 4. 影响面清单

| 文件 | 改动 |
|------|------|
| `components/AssignModal.jsx` | Form.List 多单位组（单位/说明/频率）；跨组单位互斥；组增删；附件共享不变 |
| `pages/ZaitanDetail.jsx` | handleAssignOk 适配新结构（groups → 按单位拆分并带频率）；mock 种子补频率+时间相对化；分派 tab 增加频率标签与达标状态；消息文案更新 |

## 5. 验收要点

1. 一次分派可配置 ≥2 组，各组单位/说明/频率独立；同一单位不可出现在两组；
2. 提交后分派 tab：同组单位的事项说明与频率一致，跨组互不相同；
3. 分派消息（切换到对应单位视角）含频率要求文案；
4. 存量演示数据：企服局（7 天前分派、无反馈）显示「已超期」红标；科创局（近期已反馈）显示正常；
5. 反馈提交后达标状态即时刷新；标记完成后不再显示达标状态；
6. `npm run build` 通过，无控制台运行时错误。
