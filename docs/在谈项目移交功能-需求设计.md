# 在谈项目移交功能 - 需求设计

> 版本：v1.0　|　日期：2026-09-09　|　状态：待确认
> 关联：《在谈阶段字段调整-需求设计》v1.0（已实施）

## 1. 背景与目标

部分项目由投促局完成谋划、洽谈后，需转交园区承接后续**转签约、落地**工作。本次在在谈阶段新增「移交」能力：

- 移交对象：**某个园区**（一次一个）；
- 移交后：投促局与该园区**双方均可查看和操作**该项目；
- 移交**仅支持一次**，完成后双方入口隐藏；
- 全流程留痕：进展记录 + 园区消息提醒 + 园区列表新增项目。

## 2. 现状依赖（demo 机制）

| 机制 | 现状 | 复用方式 |
|------|------|----------|
| 视角体系 | `useViewRole()`：sponsor=市投促局（全量可见）；接收方按 deptKey 过滤 | 直接复用 |
| 园区枚举 | `assignConfig.ALL_UNITS` 中含 4 个园区：未来科技城 wljs、光谷生物城 ggswc、光谷中心城 ggzx、东湖综合保税区 bq | 移交目标下拉数据源 |
| 站内信 | `msgStore.addMessage({ toDeptKey, ... })`，coop 类消息点击可跳项目 | 移交提醒走同通道 |
| 接收方列表可见性 | Zaitan.jsx：`ASSIGNED_PROJECT_IDS`（分派给我的项目） | **∪ 移交给我的项目** |
| 接收方详情权限 | `hasAccess = assignList.some(分派给我)` | **∪ 移交给我** |
| 进展时间线 | 详情页本地 state，跨会话不持久 | 移事件写入全局 store，详情构造时回放 |

## 3. 功能设计

### 3.1 移交入口（仅发起方可见 + 未移交）

| 位置 | 形式 |
|------|------|
| 在谈列表行「更多」菜单 | 新增「移交」项，位于「分派」与「更新决策节点」之间 |
| 在谈详情顶部按钮区 | 新增「移交」按钮，位于「分派」之后 |
| 在谈详情「更多」下拉 | 新增「移交」项，位于「编辑」之前 |

显隐规则：`isSponsor && !transferStore.hasTransferred(projectId)`；已移交后**双方**入口全部隐藏（接收方本无入口，发起方按记录隐藏）。

### 3.2 移交弹窗（新组件 `TransferZaitanModal`）

| 字段 | 控件 | 必填 | 说明 |
|------|------|------|------|
| 移交至园区 | Select 单选 | ✅ | 枚举 4 个园区（不含区直部门/街道/平台公司） |
| 移交说明 | TextArea | ❌ | 最多 200 字，随进展记录留痕 |

提交时**二次确认**（Modal.confirm）：展示目标园区 + 说明，明确提示「移交后该项目由双方共同管理，且**不可再次移交**」。确认后执行 3.3。

### 3.3 移交成功后的联动（4 件事）

1. **全局移交记录**：写入新全局 `transferStore`（见 3.4），记录 { 项目、目标园区、说明、移交人、时间 }；
2. **进展信息新增系统事件**：`项目已移交至「XX园区」`（含说明与移交人），发起方当前页面即时插入；接收方打开详情时从 store 回放该事件（保证双方都能看到）；
3. **园区消息提醒**：`msgStore` 新增 coop 消息 → 标题【项目移交】，内容「"市投促局"已将"项目名"移交至贵单位，请及时跟进后续转签约、落地工作」，可点击跳转详情；
4. **园区在谈列表新增项目**：接收方列表可见范围 = 分派给我的 ∪ **移交给我的**；被移交项目在园区视角下完整可见、可操作（进展汇报、编辑、决策节点、转签约、退库等，同分派项目口径）。

### 3.4 全局移交记录 `transferStore`（新增于 viewStore.js）

```js
// transfers: [{ id, projectId, projectName, toDeptKey, toDeptName, reason, by, time }]
transferStore = {
  getTransferByProject(projectId)   // 未移交返回 null → 用于按钮显隐
  getTransfersByDept(deptKey)       // 移交给某园区的全部记录 → 列表可见性
  hasTransferred(projectId)
  addTransfer(record)               // 触发订阅刷新（列表/详情/按钮同步更新）
  subscribe(fn)
}
```

配套 `useTransferStore()` hook（subscribe 模式，与 useImported 一致）。内存态，刷新重置（demo 口径，同消息/分派）。

### 3.5 权限矩阵

| 视角 | 移交前 | 移交后 |
|------|--------|--------|
| 市投促局（sponsor） | 可见可操作，可移交 | 可见可操作，**移交按钮隐藏** |
| 被移交园区 | 不可见 | 列表新增该项目；详情可看可操作；**无移交入口** |
| 其他单位 | 不可见（未分派/未移交） | 不可见 |
| 同项目二次移交 | — | 任何一方均不可（无入口 + store 校验兜底） |

## 4. 影响面清单

| 文件 | 改动 |
|------|------|
| `store/viewStore.js` | 新增 transferStore + useTransferStore |
| `components/TransferZaitanModal.jsx` | 新建：选园区+说明+二次确认 |
| `pages/Zaitan.jsx` | 更多菜单加「移交」项（按 hasTransferred 隐藏）；接收方可见性 ∪ 移交记录；绑定弹窗与成功回调 |
| `pages/ZaitanDetail.jsx` | 顶部按钮区+更多下拉加「移交」；hasAccess ∪ 移交给我；progressList 构造回放移交事件；成功后插入进展+发消息 |

**不动**：签约/落地/谋划/退库模块、分派 AssignModal、统计看板、消息中心（复用现有 coop 渲染）。

## 5. 验收要点

1. sponsor 视角三处入口均可见「移交」；选园区提交 → 二次确认 → 成功提示；
2. 成功后：详情进展时间线顶部出现「项目已移交至「XX园区」」系统事件；消息中心（园区视角）出现【项目移交】且可跳详情；
3. 切换「未来科技城」视角：在谈列表出现该项目，详情可查看、可进展汇报/编辑/转签约；
4. 移交后再看双方列表与详情：「移交」入口均已消失；
5. 切换其他园区视角（如光谷科投集团）：看不到该项目；
6. `npm run build` 通过，无控制台运行时错误。
