# 签约项目退库（投促局审核）- 需求设计文档

> 版本：v1.2（2026-09-10）
> 状态：已确认（v1.1 复用「标记退库」入口/审核入口移至退库列表；v1.2 已驳回记录保留在退库列表，重新提交后切回待审核）

## 1. 背景与现状

### 1.1 现有退库能力
| 阶段 | 退库方式 | 审核 |
|---|---|---|
| 谋划 | 列表更多操作「标记退库」→ 说明（非必填500字）+ 二次确认 → 直接退库 | 无 |
| 在谈 | 详情更多操作「标记退库」→ 同上 | 无 |
| 签约 | **无退库功能** | — |

- 退库项目统一进入「项目退库」菜单页（Tuiku.jsx），含原阶段标签（谋划/在谈）、退库说明、退库时间、操作人。
- 已退库项目不可恢复、不可编辑，仅可查看（TuikuDetail.jsx）。

### 1.2 本轮需求
已签约项目也支持退库，但与谋划/在谈不同：**退库需投促局审核，审核通过后方退库成功**。

## 2. 需求分析

### 2.1 业务流程

```
园区/投促局发起退库申请
        │
        ▼
┌──────────────────┐      ┌──────────────────────────────┐
│ 项目进入「退库审核中」│ ──▶ │ 投促局（sponsor视角）审核        │
│ 状态（锁定编辑操作） │      │  ├─ 通过 → 项目移出签约列表，    │
└──────────────────┘      │   │   进入「项目退库」列表        │
                          │  └─ 驳回 → 恢复正常状态，        │
                          │       通知申请人（附驳回意见）    │
                          └──────────────────────────────┘
```

### 2.2 状态机（签约项目维度）

| 状态 | 说明 | 可见标识 |
|---|---|---|
| 正常 | 无退库申请（或申请已被驳回后回到正常） | — |
| 退库审核中 | 已提交申请，等待投促局审核 | 仅详情标题旁橙色 Tag「退库审核中」（列表不展示） |
| 已退库 | 审核通过 | 从签约列表移除，进入项目退库列表（原阶段=签约） |
| 已驳回 | 审核驳回 | 项目恢复正常状态、可编辑可再次申请；**驳回记录保留在项目退库列表，状态「已驳回」**；消息通知驳回意见；重新提交后该记录状态切回「待审核」 |

### 2.3 角色与权限

| 视角 | 能力 |
|---|---|
| 园区/部门（非 sponsor） | 发起退库申请；接收审核结果消息 |
| 投促局（sponsor，isSponsor=true） | 发起退库申请（同样需走审核流）；审核待审项目（通过/驳回） |

## 3. 功能设计

### 3.1 入口（2 处，复用在谈「标记退库」样式）

| 位置 | 形式 | 说明 |
|---|---|---|
| 签约列表操作列 | 「更多」下拉新增「标记退库」（红色危险项 + PauseCircleOutlined，位于编辑之后，与在谈样式一致） | 仅正常状态显示；审核中项目隐藏 |
| 签约详情操作区 | 直接平铺「标记退库」按钮（红色 danger 样式），位于「推进落地」之后 | 不进更多下拉，按钮直接展示 |

### 3.2 退库申请弹窗

- 结构与谋划/在谈退库弹窗同构（复用同一交互样式）：项目名称 + 二次确认文案 + 退库说明 TextArea（非必填，最多500字）
- 文案差异：
  - 标题「确认退库」；确认按钮「确认退库」（与在谈一致）
  - 提示语：「提交后需投促局审核，审核通过后退库生效。退库审核期间项目将锁定编辑操作。」
- 提交后：
  - 项目进入「退库审核中」状态（仅详情展示 Tag）
  - 详情进展信息自动新增一条系统记录：「已提交退库申请：{说明}」
  - 发送消息给投促局（sponsor）：『"XX单位"提交了"项目名"的退库申请，请及时审核』

### 3.3 投促局审核（入口：项目退库列表）

- **项目退库列表新增「审核状态」列**：
  - 历史退库记录（谋划/在谈 mock）：「已退库」（默认样式）
  - 签约退库申请待审核：「待审核」（橙色 Tag），sponsor 可审核
  - 签约退库申请已通过：「已退库」
  - 签约退库申请被驳回：「已驳回」（红色 Tag），**保留在列表中但不可再审核**（操作列不显示「审核」按钮）
- **审核操作**：sponsor 视角下，仅「待审核」行的操作列显示「审核」按钮 → 打开审核弹窗
- **审核弹窗**：
  - 申请信息只读展示：项目名称、申请人（单位-姓名）、申请时间、退库说明
  - 审核结论 Radio：通过 / 驳回（必填）
  - 审核意见 TextArea：驳回时必填（最多500字），通过时选填
- **审核通过**：
  - 项目从签约列表移除，退库列表中该记录状态变为「已退库」
  - 详情进展记录：「退库审核通过，项目已退库」
  - 消息通知申请人单位：『"项目名"退库申请已通过』
- **审核驳回**：
  - 项目恢复正常状态（可编辑、可再次申请），退库列表中该记录**保留**，状态变为「已驳回」
  - 详情进展记录：「退库申请被驳回：{意见}」
  - 消息通知申请人单位：『"项目名"退库申请被驳回：{意见}』
- **重新申请（同一项目）**：
  - 驳回后项目回到签约列表正常状态，可再次「标记退库」
  - 再次提交时**复用同一条退库列表记录**，状态由「已驳回」切回「待审核」，更新申请人/时间/说明，恢复可审核

### 3.4 审核中锁定规则

「退库审核中」项目：
- 列表：隐藏「落地」「编辑」「申请退库」，仅保留「详情」+「进展汇报」
- 详情：隐藏「编辑」「推进落地」「申请退库」，仅保留「进展汇报」「AI 摘要」+（sponsor）「退库审核」
- 基础信息可正常查看

### 3.5 项目退库列表（Tuiku.jsx）

- 原阶段新增「签约」枚举（Tag 色 volcano/橙红）
- **新增「审核状态」列**（见 3.3）
- `buildTuikuList()` 合并 tuikuAuditStore 动态签约申请（pending/approved/rejected 全部保留，置于 mock 项之前）
- 退库详情（TuikuDetail）兼容签约来源项目：进展中展示申请/审核通过两条系统记录

## 4. 技术设计

### 4.1 新增 store（viewStore.js）

```js
// 退库审核store（签约项目退库：申请 → 投促局审核 → 通过/驳回）
// audits: [{ id, projectId, projectName, reason, applicantDeptKey, applicantDeptName,
//            applyTime, status: 'pending' | 'approved' | 'rejected',
//            auditTime, auditor, auditOpinion }]
tuikuAuditStore = {
  getByProject(projectId)      // 项目当前审核记录
  hasPending(projectId)        // 是否审核中
  addApply(record)             // 提交申请：已有 rejected 记录则复用该记录
                               //（status 重置为 'pending'，更新申请人/时间/说明），否则新建
  audit(id, { result, opinion, auditor })  // 审核：result='approved'|'rejected'
  getAuditList()               // 全部审核记录（供 Tuiku 列表合并，含已驳回）
  subscribe(fn)
}
```

### 4.2 消息（复用 msgStore.addMessage）

| 时机 | toDeptKey | 内容 |
|---|---|---|
| 提交申请 | sponsor | 『"XX单位"提交了"项目名"的退库申请，请及时审核』 |
| 审核通过 | 申请人单位 | 『"项目名"退库申请已通过，项目已正式退库』 |
| 审核驳回 | 申请人单位 | 『"项目名"退库申请被驳回：{意见}』 |

### 4.3 状态存续

- 审核状态存于 tuikuAuditStore（内存态，demo 刷新后重置，与 transferStore 一致）
- 签约列表/详情通过 `hasPending(projectId)` + `getByProject(projectId).status` 驱动 Tag 与按钮显隐

## 6. 待确认项

均已按默认方案执行：

1. 所有视角均可发起申请；投促局发起同样走审核流（不自审豁免）
2. 审核中锁定编辑/推进落地（仅保留查看 + 进展汇报）
3. 驳回后可再次申请
4. 投促局单级一审终审
