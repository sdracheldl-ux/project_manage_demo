# 谋划阶段字段调整与“责任单位”新增 - 需求设计

> 版本：v1.1（2026-09-04）
> 状态：待评审
> 范围：仅影响前端 DEMO；所有演示数据纯前端模拟，不涉及真实接口。

## 0. 背景与目标

客户沟通后提出以下调整诉求：

1. 谋划阶段填报字段精简，仅保留项目名称、内外资、来源地、产业类别、行业类别、项目简介；
2. 计划投资总额提前到谋划阶段填报（现仅在“转在谈”时填写）；
3. 新增“责任单位”字段（**多选下拉**，枚举覆盖 投促局/园区/国企平台/区直部门/街道 等），贯穿谋划、在谈、签约、落地四个阶段，退库项目同步记录；
4. 字段调整需同步梳理列表页筛选条件、列表字段、详情页、编辑页等关联界面。

目标：以字段为载体，把“项目归口责任单位（可多家协同负责）”的决策**前移到谋划阶段**，让招商一线人员在录入时即可为项目挂接责任单位，并保证该信息随项目阶段流转、可追溯。

## 1. 字段方案

### 1.1 谋划阶段字段清单

| 类别 | 字段 | 控件 | 必填 | 说明 |
|---|---|---|---|---|
| 保留（填报） | 项目名称 | 文本 | ✅ | ≤40 字 |
| 保留（填报） | 内外资 | 下拉（内资/外资） | ✅ | 联动来源地选项 |
| 保留（填报） | 来源地 | 级联（国内省-市 / 国外国家） | ✅ | 依内外资切换 |
| 保留（填报） | 产业类别 | 下拉（农业/工业/服务业） | ✅ | |
| 保留（填报） | 行业类别 | 级联（门类/大类） | ✅ | |
| 保留（填报） | 项目简介 | 多行文本 | ✅ | ≤999 字 |
| **新增（填报）** | **计划投资总额（亿元）** | 数字 | ✅ | 原在“转在谈”填写，提前至谋划 |
| **新增（填报）** | **责任单位** | **多选下拉（分组，单选值）** | ✅ | 至少选 1 项；见 1.2 |
| 系统信息（保留，不属填报项） | 申报人、申报时间、序号等 | - | - | 列表/详情继续展示 |
| 隐藏（后移到转在谈补充） | 项目分类、对应965产业链、投资主体、投资主体联系人、联系电话 | - | - | 存量演示行的历史值在谋划界面**一并隐藏**，不展示 |

> 原则：谋划阶段“信息够判断归口即可”，主体实力类、决策类字段统一放到转在谈/在谈采集，避免一个界面信息过载。

### 1.2 责任单位字段定义

- 界面名称：**责任单位**
- 控件：**多选下拉**，选项按单位类别分组展示（Select 支持 OptGroup），可搜索、可多选；不使用自由文本框。
- 是否必填：是（至少选 1 项）。
- 取值结构：**数组**（单元素也是数组），各阶段携带/编辑均为数组；列表与详情以多个 Tag 展示。

**枚举分组（默认字典，v1.1 已确认）**：

| 分组 | 单位 |
|---|---|
| 投促局 | 市投促局、区投促局 |
| 园区 | 未来科技城、光谷生物城、光谷中心城、东湖综合保税区、光电园、服务业园、智造园、中华园 |
| 国企/平台公司 | 光谷科投集团、光谷人才集团、武汉高科集团、光谷产投、光谷金控、湖北科投 |
| 区直部门 | 组织部（人才工作局）、宣传部、发改局、科创局、企服局、规划局、建设局、金融局、自贸改革创新局 |
| 街道 | 佛祖岭街道、豹澥街道、九峰街道 |

> 字典说明：演示数据以 `constants/assignConfig.js` 的 `ALL_UNITS` 为基础扩展而来（真实环境由 OA/组织接口提供）；若客户提供标准单位清单，替换该常量即可。
- 内部键建议：新增数据键 `responsibleUnits`（camelCase，数组），避免与现有 `负责单位`（签约/落地 raw 键，字符串）、`负责单位`在 QianyueEditModal 中被当作“区投促局联系人”别名的既有逻辑冲突。枚举常量统一收敛到 `constants/projectEnums.js`（如 `RESPONSIBLE_UNIT_GROUPS`，含分组结构与全量选项），全站复用。

### 1.3 计划投资总额字段定义

- 界面名称：计划投资总额（亿元）
- 控件：数字输入，单位亿元，>0，2 位小数，必填。
- 规则：谋划阶段填报后，在转在谈/各阶段编辑中**仍允许修改**（作为信息补录/纠错入口）。
- 内部键：沿用 `investAmount`（数值键）。注意现有数据键存在**全角/半角不一致**（谋划/在谈 mock 用 `投资金额（亿元）`，签约/落地用 `投资金额(亿元)`，统计看板用半角键导致谋划/在谈存量金额恒为 0），本次一并收敛读写口径，避免新填报金额“列表能显示、统计算不出”。

## 2. 阶段流转规则

| 阶段 | 责任单位 | 计划投资总额 |
|---|---|---|
| 谋划 | 新增/编辑时录入（必填） | 新增/编辑时录入（必填） |
| 谋划 → 在谈（转在谈） | 自动带出，弹窗内可见，可修改 | 自动带出，弹窗内可见，可修改 |
| 在谈 | 列表/详情展示；编辑弹窗可修改 | 列表/详情展示；编辑弹窗可修改 |
| 在谈 → 签约（转签约） | 带出并随弹窗可改 | 带出并随弹窗可改 |
| 签约 | 列表/详情展示；编辑弹窗可修改 | 同责任单位 |
| 签约 → 落地（转落地） | 带出并可改 | 带出并可改 |
| 落地 | 列表/详情展示；编辑弹窗可修改 | 同责任单位（落地详情金额字段按现结构展示） |
| 退库 | **只读**：从原项目同步记录，退库列表/详情仅展示，不可修改 | 只读：随退库记录快照展示 |

其他约束：
- “责任单位”是项目级属性，随项目编号唯一对应，跨阶段不因流转产生多个副本；各阶段编辑是**修改同一个值**（DEMO 中以路由内数据为准）。
- 退库记录 `buildTuikuList()` 需从原项目带出责任单位与计划投资总额，写入历史快照。

## 4. 交互与一致性约束

1. 责任单位下拉在所有页面使用同一枚举与分组结构、同一宽度规范（140px 级筛选下拉统一宽度），可搜索；多选值顺序按用户选择顺序保存。
2. 编辑/新增表单沿用既有 960px 两列布局规范。
3. 列表“责任单位”列建议放在“投资主体/金额”附近、允许列管理显隐；多值以 Tag 展示（最多显示 3 个 + “+N”收起）。
4. 责任单位为空（历史缺值）时，列表/详情统一回退显示为 `-`；详情区以“责任单位”标签组回显。

## 5. 验收要点

- [ ] 谋划新增：仅保留字段可见，计划投资总额必填、责任单位至少选 1 项；新增后列表金额不再为 0、责任单位以 Tag 正常展示。
- [ ] 谋划编辑：来源地、行业类别可编辑；隐藏字段不出现在编辑弹窗；责任单位可增删。
- [ ] 谋划列表/详情：投资主体、项目分类等历史值不展示；责任单位筛选项生效。
- [ ] 转在谈：计划投资总额、责任单位（多值）已带出并可改；其余必填项补齐后提交。
- [ ] 在谈/签约/落地：列表责任单位 Tag 列与多选筛选可用；详情回显；编辑弹窗可修改；转阶段弹窗带出。
- [ ] 退库：退库记录带出责任单位（多值）与金额；退库详情只读展示。
- [ ] 统计看板、研判、消息等既有功能回归不受影响。

## 6. 风险与待确认事项

1. **责任单位 vs 负责单位（统计口径）**：本版“责任单位”为独立多选字段，与签约/落地的“负责单位”（字符串、园区）及统计园区排名口径并存。若后续业务要求归口唯一化，需要一次专项统一（把统计源切到责任单位），请知悉该技术债。
2. **多选数量上限**：默认不设上限（下拉 + 搜索，Tag 折叠展示）；如客户要求限制主责 1 家 + 协责 N 家，需再加“主责单位”子字段，当前不实现。
3. 谋划字段瘦身后，谋划列表可能大量字段为空导致行信息单薄，是否通过“展开更多”等弱化展示，按实施时视觉评审决定。
